## 2. 构件 → 系统 对照

| 应县木塔 | 本系统 | 说明 |
|---|---|---|
| **双层套筒**（内槽 + 外槽，两圈柱网） | **双塔** | 内槽 = 权威 / `ledger/`，不许动；外槽 = 执行 / worktree，随便动 |
| **四个暗层**（夹在两明层之间，外面看不见） | **门禁与证据** | 交付物表面看不见，但正是它承重 |
| **54 种斗拱**（同一座塔，没有两个节点用同一种接口） | **定制的 acceptance** | 每张任务卡的验收条款按受力定制，不是模板糊上去 |
| **不用一根钉** | **spec 冻结 + handoff 契约** | 不靠胶水（人情、记忆、“我记得改过了”）自锁 |
| **柔性抗震，晃而不散** | **worktree 容错** | worktree 内允许乱、允许试错；契约节点不允许破 |
| **逐层收分**（上小下大） | **权限逐层收紧** | executor < reviewer < supervision < owner |
| **塔刹**（顶上那一小段铁件） | **owner 四闸** | 最顶端那一小段，决定整座塔归谁 |
| **历代修缮**（并非一次建成永逸） | **纠偏单 + 定期维护** | 诚实注脚：别把“千年”当免维护承诺 |

## 3. 四条设计约束（从塔里读出来的，不是装饰）

1. **暗层原则。** 门禁与证据必须在交付物表面之下真实存在。只靠“看起来对”的验收，等于没有暗层。
2. **冗余原则。** 每个关键节点至少两条独立路径（人工 + 脚本，或双人复核）。单点失效不等于失据。
3. **可修原则。** 只追加的 `ledger/` 会积累债务；必须有纠偏单与定期复盘，否则“千年不倒”退化为“带病运行”。
4. **柔性原则。** 错误应被限制在局部（worktree、单任务卡），不得沿契约节点传导。允许出错，不允许失据。

## 4. 命名层级与边界

| 层级 | 名字 | 用途 |
|---|---|---|
| 代号 | **应县木塔** | 对话、文档、对外叙事 |
| 短代号 | **Yingxian** | 目录 / 仓库 / 文档 ID（ASCII 安全） |
| 短写 | `YX`、`YX-001` | 实例别名、图表标注 |
| 实例 | `tower-dsh` | 保持不变，它就是“第一座塔” |
| CLI | `towerctl` | **不改名**；`yxctl` 仅留给未来新工具 |

**禁止与已否决：**

- 不改 `tower-dsh` 实例名——已长进路径、ledger、handoff ID、envelope ID，改名等于动权威事实。
- 不改 `towerctl` 命令名——同上。
- 不把代号写进机器可读状态（`phase` / `status` / `envelope_id` 等枚举值保持 ASCII 契约值）。
- 不叫 `Vibe*`。本系统的卖点是**反 vibe** 的：凭证据慢一点，但不会翻车；招牌写“凭感觉”会自相矛盾。

## 5. 事实口径（写文档时照此）

- 应县木塔，本名佛宫寺释迦塔，山西朔州应县；辽清宁二年（1056）建，至 2026 年为 **970 年**（不写“千年”）。
- 高约 **67.31 m**（通行说法）；外观五层六檐，内部九层、含四个暗层。
- 全塔不用钉，榫卯 + 斗拱结合；斗拱 **54 种**（通行说法）。
- 民间与比萨斜塔、埃菲尔铁塔并称“世界三大奇塔”（**通行说法，非学术定论**）。
- 历经多次地震与战火仍存；现塔身已有倾斜，修缮方案长期论证中。
- 本系统**不**宣称“千年不倒”式免维护——见第 3 节第 3 条。
